# Agent Note: 侧栏粘贴图片

Status: implemented

## Problem

旧版用一条本地存储记录保存各日期的便签。图片体积远大于文字。如果把图片塞进便签对象，编辑一行文字、勾掉一件事或打开任意日期时，都要读取并传送全部历史图片。

## Decision

便签用可选的 `imageIds` 引用独立的本地存储键，旧记录缺少这个字段时按空附件处理。侧栏只读取当前页和编辑器需要的图片。后台仍在原写入队列内更新便签，把新附件和便签放在一次 `storage.local.set` 里提交。历史复制共享原图引用。移除附件时，只有全本找不到引用的键才会随该次写入置空，提交成功后再移除空键。

输入框通过用户触发的粘贴事件接收位图。保存前转成 WebP，长边上限为 2200 像素。扩展声明 `unlimitedStorage` 给本地图片留出空间。

## Alternatives considered

图片直接放在原便签对象里只需一次读取，数据结构也最简单，但所有历史图像会进入每次写入和跨窗口更新。把附件存进 IndexedDB 能直接存二进制 Blob，但沿用当前便签存储时需要协调两套数据库的提交与失败恢复。

## Consequences

侧栏加载图片需要额外读取本地存储，图片采用压缩后的副本。附件读取和普通便签更新的体积保持独立。Chrome 测试覆盖纯图与图文记录、重开、带图跨日复制、清理未引用附件，以及读取旧版纯文字记录。
